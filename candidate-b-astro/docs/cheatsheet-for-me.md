# Шпаргалка: как устроен сайт (простыми словами)

## Схема одной страницы

```
Браузер просит /company
      ↓
Cloudflare Worker (src/worker.ts)  — «сервер», который живёт у Cloudflare
      ↓
Astro (src/pages/company.astro)    — собирает HTML из компонентов
      ↓ берёт данные
src/data/*.json (команда, таймлайн…) и вакансии (data/roles.json → KV)
      ↓
Готовый HTML + CSS + маленький JS уходят в браузер
```

Главная мысль: **страница = шаблон + данные**. Тексты и фото лежат отдельно
от вёрстки, поэтому контент можно менять, не трогая код.

## Куда смотреть, если спросят «а где…»

| Вопрос                            | Файл                                                   |
| --------------------------------- | ------------------------------------------------------ |
| Шапка и меню                      | `src/components/siteHeader.astro` + `public/js/nav.js` |
| Общий каркас страниц              | `src/layouts/BaseLayout.astro`                         |
| Цвета, отступы, скорости анимаций | `src/styles/tokens.css`                                |
| Команда, таймлайн, офисы          | `src/data/*.json`                                      |
| Проверка формата данных           | `src/content.config.ts` (zod-схемы)                    |
| Вакансии                          | `data/roles.json`, `src/lib/roles/*`                   |
| Форма отклика (backend)           | `src/pages/api/apply.ts`, `src/lib/apply/schema.ts`    |
| Проверка «жив ли сайт»            | `src/pages/api/health.json.ts`                         |
| Расписание (cron)                 | `src/worker.ts`, `wrangler.jsonc`                      |
| Безопасность (CSP)                | `public/_headers`                                      |

## 10 решений и ответ в одно предложение

1. **Astro, а не React-приложение.** Сайт в основном контентный; Astro отдаёт
   готовый HTML и почти не шлёт JS — быстро и хорошо для SEO.
2. **Cloudflare Workers.** Код выполняется близко к пользователю, нет своего
   сервера, который надо обслуживать; есть бесплатный уровень.
3. **Контент в JSON.** Контент-менеджер правит данные, не вёрстку; формат
   проверяется автоматически.
4. **Zod-схемы.** Если в JSON ошибка (нет фото, короткий текст), сборка падает
   сразу, а не ломается сайт у посетителей.
5. **Вакансии в KV + cron каждые 10 минут.** Список обновляется без
   пересборки сайта; если источник недоступен, остаётся последняя копия.
6. **API `/api/apply`.** Форма отправляет данные на сервер, где они
   проверяются заново: проверке в браузере доверять нельзя.
7. **Cloudflare Turnstile (в CSP).** Защита формы от ботов без капч с
   светофорами.
8. **CSP в `_headers`.** Браузеру разрешено грузить скрипты только с нашего
   домена — это защита от внедрения чужого кода (XSS).
9. **Дизайн-токены.** Цвета и размеры заданы переменными в одном месте, чтобы
   сайт выглядел единообразно и менялся одной правкой.
10. **Тесты (vitest) и CI в GitHub Actions.** Слияние в `main` само проверяет и
    выкладывает сайт; ошибки ловятся до продакшена.

## Если спросят то, чего не знаешь

> «Я использовала AI как инструмент и понимаю структуру: вот схема. В детали X
> я не углублялась, разберусь — вот где это лежит.»

Это нормальный ответ для junior. Хуже — делать вид, что знаешь больше.

## Привычка на 2 минуты после каждой правки

1. `git diff` — посмотри, какие строки поменялись.
2. Спроси: «объясни это в 3 предложениях и почему именно так».
3. Запиши ответ одной строкой в `docs/journal.md`.

За 2 недели это даст больше понимания, чем любой курс.
